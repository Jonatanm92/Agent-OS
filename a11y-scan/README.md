# E-commerce Accessibility Risk Scan

A local CLI that scans a public e-commerce site for accessibility problems,
groups and prioritizes them, and produces a report good enough to sit behind a
fixed-price engagement **that a human reviews before delivery**.

The tool produces the draft. A person signs it off. That split is the product:
automated testing detects roughly a third of WCAG failures, so anything sold as
"complete" on automated output alone would be a lie.

```
npm install
npm run full-scan -- https://dinbutik.se      # full scan → HTML + JSON + handoff
npm run prescan   -- https://dinbutik.se      # internal prospect summary
npm test                                      # 189 tests
```

---

## Commands

| Command | What it does |
|---|---|
| `npm run full-scan -- <url>` | Up to 12 pages, depth 2. Writes `out/<domain>-<date>.html`, `.json` and `-handoff.md`. |
| `npm run prescan -- <url>` | Up to 4 pages, depth 1. Prints an internal lead summary to stdout. Not for sending. |
| `npm test` | Full suite, including browser-backed integration tests. |
| `npm run typecheck` | `tsc --noEmit`. |
| `npm run examples` | Regenerates `examples/` from the fixture shop. |
| `npm run fixture-server` | Serves the intentionally broken demo shop for manual poking. |

> **Why `full-scan` and not `scan`.** npm treats `pre<name>` as an automatic
> hook, so with a script named `scan`, `npm run scan` silently runs `prescan`
> first and aborts on its missing argument. The two names cannot coexist, and
> `prescan` is the name the brief fixes. The underlying CLI command is still
> `scan` — `npx tsx src/cli.ts scan <url>` works directly.

Options: `--out <dir>`, `--max-pages <n>` (may lower the budget, never raise it),
`--allow-private-targets` (testing only — prints a warning banner).

### Requirements

Node 20+. Playwright downloads Chromium on `npm install`; if the environment
already has one, set `A11Y_CHROMIUM_PATH` and it will be used instead.

## What it checks

**axe-core** for WCAG 2.x A/AA, plus checks axe does not attempt:

| Check | Criterion |
|---|---|
| Touch target size at a phone viewport | 2.5.8 (WCAG 2.2) |
| Focus indicator actually paints on focus | 2.4.7 |
| Horizontal overflow at 320px | 1.4.10 |
| Zoom suppressed by the viewport meta tag | 1.4.4 |
| Generic link text ("läs mer", "click here") | 2.4.4 |
| Checkout fields missing `autocomplete` | 1.3.5 |
| Positive `tabindex` | 2.4.3 |
| Clickable elements not reachable by keyboard | 2.1.1 |
| Missing skip link | 2.4.1 |
| Missing `h1` | 1.3.1 |

`ARCHITECTURE.md` explains why pa11y and Lighthouse were evaluated and left out.

## What it does with what it finds

- **Groups** by rule plus normalized component, so one defect on forty pages is
  one finding with a page count, not forty findings.
- **Rates severity** by position in the purchase funnel, not by axe's
  context-free `impact` — a nameless button in the cart outranks one in the
  footer.
- **Estimates effort** from the number of components to edit, not pages
  affected. One shared template across forty pages is a small fix.
- **Labels every finding** `AUTOMATICALLY VERIFIED` or `MANUAL CHECK REQUIRED`,
  and never records a manual check as passed.
- **Generates a manual verification script** covering keyboard navigation, focus
  order, menus, modals, cookie consent, variants, quantity, add-to-cart, cart
  editing, search, form errors, mobile navigation, zoom and screen-reader labels.

## Safety

Target sites are hostile input from the URL to the rendered report.
`THREAT-MODEL.md` is the full account; the short version:

- **http/https only.** `file:`, `javascript:`, `data:` and friends are refused
  by an allowlist, including through redirects.
- **No private networks.** DNS is resolved and every returned address checked
  against loopback, RFC1918, CGNAT, link-local (the cloud metadata range) and
  the IPv6 equivalents including IPv4-mapped forms.
- **Nothing destructive.** GET only. No form is submitted, no button clicked,
  no order placed. Logout, admin and cart-mutation URLs are dropped from the
  queue. Authentication is never attempted or bypassed. `robots.txt` is obeyed.
- **Bounded.** Page, depth, queue, timeout, response-size and wall-clock limits,
  all in `src/config.ts`.
- **The report is inert.** Every target-derived string is escaped; the document
  contains no `<script>` and no inline handlers. Proved by loading it in a real
  browser with hostile payloads: `tests/report-dom.test.ts`.

## Delivery workflow

1. `npm run prescan -- <url>` — decide whether the prospect is worth contacting.
2. They buy the scan through Shopify (`docs/shopify-service-spec.md`).
3. `npm run full-scan -- <url>`.
4. **Review the draft.** Remove false positives, sanity-check severities, run as
   much of the manual script as the price supports.
5. Deliver the reviewed HTML report and the handoff.

Step 4 is not optional. Raw tool output is a draft, not a deliverable.

## This is not a compliance product

Every output states it, and the sales page must too:

> This is a technical accessibility risk scan (pre-audit). It is not legal
> advice, not a certification, and not a guarantee of compliance with WCAG, the
> Swedish accessibility legislation (LPTT) or the European Accessibility Act.

Automated testing detects only a portion of accessibility barriers. Passing every
check in this tool does not demonstrate compliance with anything.
